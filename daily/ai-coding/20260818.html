AI 编码去魅：从 vibe coding 到 craft coding 的反思

#AI 编码 #方法论 #vibe coding #代码质量 · 来源：

Peter Bloem 提出 AI 时代的编码方法论：将工作分为'做事'和'检查'两个阶段，当前 AI 无法同时胜任两者。他反对把代码全部交给 AI（vibe coding），也反对完全手工编码，而是主张'craft coding'——让 AI 当审查者检查人类写的代码，而不是让 AI 写代码人类来检查。文中用三个面包师（手工、商业化、工匠）类比三种编码风格，指出科学代码因正确性要求高是 craft coding 的最佳应用场景，并计算了该方式的能耗远低于一杯咖啡。

推荐理由：在 AI 编码工具全面普及的当下，这篇方法论文章提供了第三条路径：让 AI 做审查者而非作者，对开发者有直接实践价值。

Surfil：AI 编码代理的端侧控制平面，降本、安全、记忆三位一体

#AI 编码 #安全 #成本优化 #端侧工具 · 来源：

Surfil 是一个运行在 Claude Code、Cursor、Codex、Copilot 旁边的端侧控制平面，通过单一字节级精确的拦截点实现三类能力：Cap（测量并削减 token 成本）、Guard（拦截密钥泄露和 OWASP 评分的注入攻击）、Mind（跨代理的本地加密记忆）。其独特设计是每一项声称都以 Ed25519 签名收据证明，可离线验证、无需账号。声称零追踪（源代码绝不出设备）是架构性承诺而非设置项，卸载时逐字节恢复所有代理配置。定价仅对签名输出计费。

推荐理由：AI 编码代理的成本失控、安全风险与记忆缺失是三大现实痛点，Surfil 的签名证明机制提供了可验证的解决方案范式。

jcode：资源效率极致的开源终端编码代理，内存仅 Claude Code 的 1/20

#终端编码代理 #开源 #资源效率 #基准测试 · 来源：

jcode 是一个 Rust 编写的开源终端编码代理，核心卖点是资源效率：每个额外会话仅占约 10.4MB 内存（Claude Code 约 212MB，为其 20 分之一），10 个会话共约 100MB；首次输入延迟 48.7ms（Claude Code 需 3.5 秒）。它设计了抗污染基准（jcode bench v1），在 float-print 任务上以 398 倍加速击败 Claude Code 的 144 倍。还实现了置信度步进（置信度突增时强制复查）、自动 poking（任务未完成时自动继续）和可攀登目标（hill-climbability 评分）。

推荐理由：资源效率是代理大规模并行的瓶颈，jcode 的量级级优势代表了终端编码代理的下一个竞争维度。
