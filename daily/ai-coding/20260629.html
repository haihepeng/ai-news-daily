Graphify：面向 AI 编程助手的开源知识图谱工具

#知识图谱 #Token优化 #代码理解 #开源工具 · 来源：graphify.net

Graphify 是一款开源工具（MIT 协议，3.7k+ GitHub Stars），为 Claude Code、OpenAI Codex 等 AI 编程助手构建可查询的知识图谱。它使用 Tree-sitter 进行 AST 解析，结合 LLM 进行语义提取，通过 Leiden 算法进行社区聚类（无需向量嵌入）。核心能力包括：多模态提取（代码、文档、PDF、图片）、知识图谱构建、核心节点识别、交互式输出（HTML/JSON/Obsidian）。实测数据显示，对 Karpathy 混合语料库查询仅消耗约 1.7k token（相比朴素方式的 123k，减少 71.5 倍）。支持 /graphify、/graphify query、/graphify path、/graphify explain 等命令。

推荐理由：实用的 AI 编程增强工具，通过知识图谱大幅降低 token 消耗并提升代码理解能力。已获得社区认可（3.7k Stars），适合在大型代码库中使用 AI 助手的开发者。

清洁 GitHub 仓库诱骗 AI 编程代理执行恶意软件

#AI安全 #供应链攻击 #Claude Code #代码代理安全 · 来源：BleepingComputer

安全研究人员展示了一种针对 AI 编程代理（以 Claude Code 为例）的新型攻击手法。攻击者利用一个完全合法的 GitHub 仓库，仓库本身不包含任何恶意代码，而是通过 AI 代理的自动错误处理行为来执行恶意载荷。攻击链包括：仓库包含标准安装指令→AI 执行时遇到故意设计的错误→AI 自动运行修复命令→该命令从攻击者控制的 DNS TXT 记录中获取并执行恶意命令。Mozilla 0DIN 研究团队指出，Claude Code 并非主动决定打开 shell，而是被诱导去'修复一个错误'。该攻击目前为概念验证阶段，但可通过假招聘帖、教程等方式大规模传播。

推荐理由：对所有使用 AI 编程代理的开发者和团队具有重要警示意义，展示了 AI agent 自动化行为可能被利用的安全风险。建议了解攻击机制并关注 AI agent 的执行链披露机制。

Deburr：AI 编程代理的边缘情况系统化处理技能

#Rust开发 #代码质量 #AI Agent Skill #类型系统 · 来源：GitHub (imbue-ai)

Deburr 是为 AI 编程代理设计的结构化质量检查技能，专注于移除 AI 生成代码中积累的冗余内容——包括防御性运行时检查、冗余验证、投机性抽象和无操作包装器。核心理念是：与其在运行时检测错误状态，不如通过类型系统在编译时禁止错误状态。该技能提供了完整的处理流程：范围界定→按集群审查→合并分类→逐一执行→安全验证→最终检查。特别强调所有修改必须保持行为一致性，不确定时默认保留。附带 Rust 代码的实际示例和反模式说明。

推荐理由：对使用 AI 编程代理进行 Rust 开发的团队非常实用，提供了一套系统化的代码清理方法论。展示了如何为 AI agent 创建专业化 skill 来提升代码质量。

Clawie：快速终端编程代理，支持本地模型运行

#终端代理 #本地模型 #Rust/Python #Lean模式 · 来源：GitHub (HoratiuCode)

Clawie 是一个快速终端编程代理，支持 Rust 和 Python 双实现，核心特色是在本地机器上运行大型模型以获得速度和控制权。关键功能包括：交互式设置向导、Lean Senior Dev 模式（通过 Lean Ladder 防止过度工程化）、仓库映射（生成文件和符号排名图）、Git 集成、基于 SQLite 的 RAG 语义搜索服务、Web UI 可视化仪表盘。Lean 模式提供 lite/full/ultra/off 四个级别，可通过 /lean 命令控制。运行时默认支持较长编码会话（max_turns: 64, max_budget_tokens: 12000）。

推荐理由：开源的本地优先编程代理，Lean 模式的设计理念值得关注——防止 AI 过度工程化是一个重要方向。适合需要完全控制和隐私的开发者。
